# 基础产品部 PRD 输出规范

本规范来源于《基础产品部PRD模板【20260821】》，用于 `/yipex:prd` 的 `requirement.md`。输出必须保留以下章节、顺序和固定表头；不得用页面设计文档或 Page Spec 代替 PRD。

## 填写原则

- 文档标题使用 `【产品模块】设计日期-需求名称`，设计日期使用 `YYYYMMDD`。
- 标题后依次填写飞书项目链接和一句话需求说明。
- 未提供链接、排期、指标、接口、负责人或业务结论时，写 `[待确认：具体问题]`，不得编造。
- 不适用的章节仍保留标题，并写“本需求不涉及：原因”。
- 需求背景、现状问题、解决思路和价值评估必须分开表达，不能用同一段内容重复填充。
- 流程、模型和状态关系优先使用 Mermaid；不能确定的规则标为待确认。
- 功能按主流程阶段排序，优先级使用 `5` 到 `1`，数字越大优先级越高。
- 涉及账户状态或资金变更时，必须明确幂等、防重、一致性、自检自控和风险敞口；不能仅写“无风险”。

## 各章节最低内容要求

| 章节 | 最低要求 |
| --- | --- |
| 2.1 需求背景 | 触发背景、业务场景、提出方或外部约束。 |
| 2.2 现状问题 | 当前流程、具体问题、影响对象和可观察影响。 |
| 2.3 解决思路 | 解决方向、关键边界和不在本期处理的事项。 |
| 2.4 价值评估 | 分别说明商户价值和易宝价值；没有量化依据时标待确认。 |
| 2.5 需求范围 | 明确本期范围、不在范围和受影响系统。 |
| 3.1 设计目标 | 使用可验证的运营可用性、效率、质量或性能目标。 |
| 3.2 目标客户 | 客户类型、使用场景和规模。 |
| 3.3 目标排期 | 目标时间和倒排原因；未提供时标待确认。 |
| 4.1 业务流程与名词 | 主要场景流程、关键业务规则和术语定义。 |
| 4.2 关键模型 | 主要对象、数据关系和状态转换。 |
| 4.3 功能定义 | 按流程排序，填写固定五列表格和 5-1 优先级。 |
| 4.4 接口 | 调用方向、用途、主要入参出参、异常与幂等要求。 |
| 4.5 原型 | 原型链接及改动点入口、路径、描述、示例图和优先级。 |
| 4.6 非功能需求 | 尽量量化性能、可用性、扩展性、安全性和兼容性。 |
| 4.7 灰度策略 | 灰度对象、范围、节奏、观测指标、停止和回滚条件。 |
| 4.8 存量数据 | 是否迁移、补偿、清洗、兼容或保持不变。 |
| 4.9 资金风险 | 基本、确定性、一致性、防重、自检自控原则及风险应对。 |
| 4.10 风控对接 | 是否对接、接口与参数、相应策略和待共识事项。 |
| 5.1 相关文档 | 现有产品说明、技术方案、测试方案、执行结果、接口文档等。 |
| 5.2 遗留问题 | 按 `产品服务名称_负债名称_优先级` 记录；没有则说明无。 |
| 5.3 会议纪要 | 时间、参会人、结论、待办和负责人。 |

## 输出边界

- `/yipex:prd` 的主要交付物是 `requirement.md`，不默认生成 `page-spec.json` 或预览。
- PRD 中的页面结构与交互描述属于产品需求，不替代后续 `page-design.md`。
- 需求信息不足但不影响文档结构时继续输出，以待确认项收口；只有所属系统或关键业务结果无法确定时才暂停并询问。
