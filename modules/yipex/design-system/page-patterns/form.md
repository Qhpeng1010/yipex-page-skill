# YiPex Form Page Pattern

本文件是 `form` 页面族的按需参考，只定义普通、分组和分步表单的特有布局与流程。变体和载体选择遵循导演规则 02，通用校验、幂等、恢复和可访问性遵循 03。

高级组件、条件依赖、动态枚举、失效值清理和既有 Modal 结构保持使用 `references/form-capabilities.md` 的声明式字段协议。

## 推荐骨架

```text
Form
├── Breadcrumb (independent page)
├── Form Content
│   ├── Section / Step
│   └── Fields
├── Feedback
└── Actions
```

- 独立表单页使用真实可返回的 Breadcrumb；位置已经明确时不重复显示无信息增量的页级标题。
- 页面操作区包含次操作和唯一主操作，主操作位于最右侧。
- 使用 Ant Design `Form` 组织字段和校验，不使用仅靠自定义事件拼接的无语义输入集合。
- 长文本、备注或业务上需要完整宽度的字段可以跨列；普通字段不为填满网格随意拉伸。
- 字段说明使用 Label 右侧可聚焦帮助图标和 Tooltip；校验错误显示在字段附近。

## 页面族特有交互

| 交互 | 页面族特有结果 |
| --- | --- |
| 编辑字段 | 更新表单值和 dirty 状态，按 Contract 更新依赖字段 |
| 提交 | 完成适用校验后保存，成功进入 Contract 声明的目标 |
| 重置 | 恢复页面初始值，清除校验、提交结果和 dirty 状态 |
| 取消或返回 | 无修改时返回来源；有修改时执行 03 的离开确认 |
| 异步字段联动 | 更新选项、默认值或可见性，并重新校验受影响字段 |

## 普通表单

- 用于字段较少、无需明确分组或步骤的任务，不为视觉效果拆成多个 Card。
- 桌面可以使用一列或两列；字段顺序优先表达业务填写顺序。

## 分组表单

- 每个稳定业务主题使用一个模块；Card 只在需要明确模块边界时使用，不嵌套卡片。
- 模块标题位于 Card header，模块间距使用 01 的 Token。桌面字段网格默认三列，长内容可跨三列。
- 超宽屏下，分组表单按当前模块的字段数量最多扩为四列；字段较少的模块只创建实际需要的列并均匀分配宽度，不保留空网格列，也不让单个普通控件无限拉宽。
- 多模块表单可以使用固定吸底操作栏；操作栏必须位于 Shell 工作区、为正文预留高度且不能覆盖最后一个字段或键盘焦点。

## 分步表单

- 使用 Ant Design `Steps` 表达当前位置；当前步骤只显示本步字段和必要上下文，不重复显示相同步骤标题与说明。
- 当前步骤默认使用单列、纵向、等宽字段组：标签在上、控件在下，普通控件共享同一内容宽度并保持左边界对齐，不因字段较少而横向铺满页面。默认内容宽度由渲染器控制，页面规格不得为了填充空间自行改成多列。
- 只有页面规格显式声明步骤 `columns` 且需求确有并列录入依据时，才允许使用多列；多列必须使用等宽网格，普通字段不得混排成不规则的 `2、1、2` 结构。需要整行展示的长字段必须显式声明跨列。
- 最后一步才提交完整表单；提交期间禁止切换步骤。复核步骤使用 `Descriptions` 展示已填写信息。
- 是否允许点击步骤标题跳转由 Contract 声明；未满足依赖时不得跳过。

## 响应式

- 窄屏下表单网格切换为单列，跨列字段恢复为普通单列字段。
- 固定操作栏始终可见且不产生横向溢出；移动端键盘弹出时当前字段和主操作仍可到达。
- 分步表单可以简化次级说明，但保留当前步骤和总进度。
