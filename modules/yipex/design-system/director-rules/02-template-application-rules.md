# YiPex 页面方案与应用规则

本文件是 YiPex 页面家族、页面变体、展示形态、载体和标准/开放生成选择的唯一设计规则来源。详细 Page Pattern 只补充一个页面族特有的结构与业务交互；Recipe、Pattern 和 Capability 都不是能力白名单。

规则等级沿用 `01-visual-constitution.md` 的 `MUST`、`DEFAULT` 与 `HEURISTIC`。

## 页面家族

**YP-TPL-001 `DEFAULT`** 按用户的主要任务选择一个主页面家族，而不是按页面包含的组件数量分类。

| 主任务 | 页面家族 | 推荐骨架 | 可选区域 |
| --- | --- | --- | --- |
| 查找、比较和处理一组记录 | `list` | 查询区 + 结果区 | 汇总、批量操作、详情或表单 Overlay |
| 监控指标、趋势、分布和异常 | `dashboard` | 指标区 + 分析区 | 全局筛选、异常列表、下钻 |
| 创建或修改一个业务对象 | `form` | 表单区 + 操作区 | 分组、步骤、复核 |
| 查看一个对象的完整信息 | `detail` | 详情区 | 摘要指标、关联列表、业务操作 |
| 表达已知来源操作的最终或持续状态 | `result` | 结果区 + 下一步操作 | 摘要、重试、取消 |

**YP-TPL-002 `HEURISTIC`** 标题、关键词和字段数量只能作为证据，不能替代任务判断。一个页面包含筛选、指标、表格、表单片段或结果反馈时，不因此自动变成多个页面族；这些区域应服务于主任务。

**YP-TPL-003 `MUST`** 需求没有可靠证据命中既有页面家族时使用 `custom`。不得为了套模板强行归入最接近的页面族；`metadata.pageType` 可以使用描述性字符串，组件树可以通过 `custom` 和 `extensions` 扩展。

## 标准与开放组合

**YP-TPL-004 `DEFAULT`** `auto` 模式只有在已实现 Recipe 能覆盖本次需求中的全部已识别能力时才使用标准渲染器；未命中 Recipe、出现未登记的新能力或已登记能力尚未实现时，自动进入开放 Page Contract。只有用户显式选择 `standard` 或 `strict` 时才输出能力缺口。

**YP-TPL-005 `MUST`** 新自然语言、新组件组合和未登记能力在 `auto` / `open` 模式下必须继续生成。能力注册表用于发现复用机会和判断固定渲染器是否适用，不得阻止 Page Spec 表达新业务结构。

**YP-TPL-006 `DEFAULT`** 每次只读取一个与主页面家族匹配的 Page Pattern。Pattern 提供推荐结构与页面族特有交互；明确需求或更强业务证据可以调整结构，并通过 `presentationDecisions` 记录选择，通过 `contract.deviations` 记录对共享视觉或组件默认的偏离。

## 页面变体

**YP-TPL-007 `DEFAULT`** 表单字段较少且关系简单时使用普通表单；字段存在稳定业务主题时使用分组表单；只有存在先后依赖、阶段校验、分阶段权限或确实需要降低单步复杂度时使用分步表单。字段数量只提供辅助证据，不把长表单机械拆成步骤。

**YP-TPL-008 `DEFAULT`** 轻量且不需要用户决策的操作结果使用 `message` 或局部 `Alert`；需要解释结果、影响、参考编号、持续处理状态、恢复路径或多个下一步时使用 `result` 区域或独立结果页。结果页不代替完整详情或新的复杂任务。

## 展示形态

**YP-TPL-009 `DEFAULT`** 展示形态按“用户明确要求 → 高置信度结构证据 → 命中 Pattern 的默认方案”选择。影响主要区域或关键交互的判断写入 `page.extensions.presentationDecisions`；证据不足时不为视觉变化自行卡片化、弹层化或拆页。

| 业务结构 | 默认形态 | Ant Design 基础组件 |
| --- | --- | --- |
| 多记录、多列对齐、排序、分页、批量操作或高密度扫描 | `table` | `Table` + `Pagination` |
| 少量实体的摘要浏览，每项有独立状态或操作且需要横向比较 | `card-grid` | `Card` |
| 2–6 个单选或多选方案，每项包含标题与说明、标签、价格或能力差异 | `selectable-card` | `Radio` / `Checkbox` + `Card` |
| 普通枚举、短标签或选项较多且不需要比较说明 | `standard-choice` | `Radio` / `Checkbox` / `Select` |
| 一个业务对象的只读字段 | `detail` | `Descriptions` |
| 趋势、分布、排行或关系分析 | `visualization` | 适合任务的图表或自定义可视化 |

**YP-TPL-010 `HEURISTIC`** 自动采用 Card 至少需要两个相互支持的正向证据；出现列对齐、排序、批量操作或高密度扫描时优先 Table。卡片式选择必须同时具备选择语义、2–6 个选项和超出短标签的比较信息；只有“两个选项”不构成卡片化依据。

## 载体与页面组合

**YP-TPL-011 `DEFAULT`** 用户明确指定 Modal、Drawer、独立页面或组合页面时优先执行。未指定时，先判断是否需要保留来源上下文、任务复杂度、字段依赖、上传与复核、风险、内容长度和刷新恢复，再使用以下字段数量作为默认参考。阈值是默认方案，不是能力上限。

| 上下文内的详情或新增/编辑 | 默认载体 |
| --- | --- |
| `1–6` 个最终可见字段 | Modal |
| `7–16` 个最终可见字段 | Drawer |
| `>16` 个字段，或需要独立地址、复杂关联、长流程、分步任务或完整工作区 | 独立页面 |

字段数量按默认状态下最终可见的 `Descriptions.Item` 或表单字段计算；分组标题、纯说明和操作按钮不计入。条件字段按默认可见状态计数。`rules-index.json` 中的 `automaticThresholds` 是本规则的机器镜像，必须保持一致。

**YP-TPL-012 `HEURISTIC`** 短且连续的上下文任务优先 Modal；信息较多但仍需保留来源上下文时优先 Drawer；需要独立地址、刷新恢复、复杂关联、长流程或完整工作区时优先独立页面。明确业务证据可以覆盖字段阈值，并记录判断依据。

**YP-TPL-013 `MUST`** “弹窗/Modal”“抽屉/Drawer”“新增页面/详情页/独立页面”等能定位到具体操作的表达属于显式载体。“进入表单”“进入分组表单”“打开表单”“保存后返回列表”“流程”和模块标题只描述任务或内容结构，不单独构成拆页证据。同一操作出现互斥显式载体时先澄清。

**YP-TPL-014 `DEFAULT`** 只有载体判断为独立页面，或需求明确包含多个可独立到达的任务时才创建 Page Composition。多个模块、同页列表与表单片段、返回来源或“流程”等词本身不构成多页面证据；Modal 和 Drawer 留在来源页面中。

## 新能力沉淀

**YP-TPL-015 `DEFAULT`** 首次出现的新能力在开放 Contract 中实现并记录自然语言证据；重复出现且结构稳定时登记为 Capability；形成稳定高频组合后再增加 Recipe 或 Pattern。不得为单个案例提前增加全局硬规则。

**YP-TPL-016 `MUST`** Page Spec、Page Contract、Capability Model、Shell 和模板接口是执行契约。调整本设计决策层不得静默改变这些契约；确需升级时应单独版本化和迁移。

## 冲突顺序

**YP-TPL-017 `MUST`** 冲突按以下顺序处理：法律、安全、权限、信息真实性和可访问性；用户明确的功能目标；导演规则中的 `MUST`；用户明确的表现要求；导演规则中的 `DEFAULT`；页面 Pattern；`HEURISTIC` 与组件库默认。无法同时满足两个高优先级要求时再请求澄清。

**YP-TPL-018 `HEURISTIC`** 组件形态由任务语义而不是视觉偏好决定。复杂 Table、弹层、卡片、自定义可视化或新交互只有在帮助比较、决策、保留上下文或完成任务时采用；新能力未出现在上述矩阵时继续开放组合，不把矩阵当作白名单。
